## Açıklama
`finance-reporting.service.ts:487-492` sıralama alanını istemciden gelen değerle **şablon
literal'i içinde** kuruyor:

```ts
const sortField =
  pagination.sortBy === 'planName'
    ? 'plan.planName'
    : `plan.${pagination.sortBy}`;
query.orderBy(sortField, pagination.sortOrder || 'DESC');
```

`dto/report-filters.dto.ts:97-100`'de `sortBy?: string` yalnızca `@IsString()` ile doğrulanıyor —
**`@IsIn(...)` whitelist'i yok**. TypeORM `orderBy` argümanını parametrelemez; string olduğu gibi
SQL'e girer.

İki ayrı sorun, ikisi de gerçek:

1. **Determinizm (INV-N-001).** `sortBy=id` gelirse finansal rapor üretilmiş uuid'ye göre
   sıralanır. `financial-ordering.sh` bunu **göremiyor**: guard yalnız tırnaklı literal anahtarı
   değerlendiriyor, değişkenle verilen anahtarı değil. Faz 2 review'ında ölçüldü ve
   `INV-N-001`'e "guard blind spot" olarak yazıldı.
2. **Injection yüzeyi.** Whitelist olmadan `orderBy`'a keyfi string geçmek SQL enjeksiyon
   yüzeyidir. Bu, determinizm sorunundan bağımsız ve daha ağır.

## Neden ayrı task

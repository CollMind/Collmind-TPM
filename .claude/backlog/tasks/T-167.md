- Row-Level Security (RLS) enforced at database level

## 1. 🔴 Uygulama **superuser** olarak bağlanıyor → RLS **tümüyle etkisiz**

```
pg_roles (login yapabilenler):
  postgres | super=true | bypassrls=true | login=true      ← TEK login rolü
typeorm.config.ts:63  username: ... || 'postgres'
```

> **Superuser RLS'e tabi değildir — `FORCE ROW LEVEL SECURITY` de onu bağlamaz.**
> Bugün 43 tabloya politika yazılsa **hiçbiri uygulanmaz**, ve testler **yeşil geçer**.

Bu, `CLAUDE.md §2.7`'nin tam sınıfı: kapı kurulur, hep yeşil olur, hiçbir şey ayırt etmez.
**Ön koşul: uygulama için ayrı, `NOSUPERUSER`/`NOBYPASSRLS` bir DB rolü.**

## 2. 🔴 `v_budget_summary` RLS'i **atlar**

View sahibi `postgres`, `reloptions` NULL → `security_invoker` **kapalı** → view sahibinin
haklarıyla çalışır. Ve bu **bütçe okuma yolu**.

## 3. 🔴 TypeORM havuzu + oturum değişkeni: sızma yüzeyi

`@InjectRepository` **71 çağrı noktası / 40 dosya**, havuz ayarı yok.

- `SET` → havuza dönen bağlantıda **kalır**, sonraki isteğe sızar
- `SET LOCAL` → transaction'sız okumada **yoktur**

⚠️ Bu bir **tasarım riski**, ölçülmedi. Ölçecek deney `0056 §D.4`'te önerildi — RLS
yazılmadan **o deney koşulmalı**.

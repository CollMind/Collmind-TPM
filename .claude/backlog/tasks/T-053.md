## Açıklama
[[T-019b]] içinde "Faz 1'de sorun değil" diye devredilen borç, Team Lead incelemesinde
**canlı hata** çıktı. [[T-048]] kova filtresini eklerken (doğru bir düzeltmeydi), telafi edici
RELEASE satırı tipsiz kaldığı için [[T-033]]'ün düzelttiği hata **tipli kovalarda yeniden doğdu**.

**Zincir (statik kanıt):**
1. `budget-reservation.service.ts#releaseNetReservation` RELEASE satırını **`spendType` vermeden**
   yazıyor (`:215-226`) → `spend_type = NULL`. Gruplama da yalnız `envelopeId` (`:166`).
2. `budget.service.ts#matchesBucket` (`:51`) NULL'u yalnız `'TOTAL'` ile eşliyor
   (`bucket === 'TOTAL' ? !tx.spendType : tx.spendType === bucket`).
3. `reserveForPlan`'ın net hesabı `matchesBucket` ile filtreli (`:474`) → ON/OFF kovaları
   RELEASE'i **hiç görmüyor**; net düşmüyor.
4. `if (netOutstanding > 0 && envelopeReserves.length > 0) return` (`:490`) → reject sonrası
   resubmit **erken dönüyor, yeni RESERVE yazmıyor**.

**Sonuç:** `/submit-for-approval` ile submit → reject → resubmit yapılan planda bütçe
**sessizce rezerve edilmemiş** kalır; zarf under-encumbered olur. Plan Approved'a giderse
bütçeden düşmemiş bir plan onaylanmış olur (BRD: "Approved bütçeden düşer" ihlali).

**Neden hiçbir test görmedi:** iki submit ucu farklı kovalara gidiyor —
- `POST /plans/:id/submit` → `planService.submit` → **TOTAL (tipsiz)**; reject→resubmit döngüsü
  **A16** ile kapsanıyor → geçiyor, çünkü tipsiz uzayda RELEASE görünür.
- `POST /plans/:id/submit-for-approval` → approval-workflow → **ON/OFF (tipli)**; **A8c** yalnız
  submit'e kadar gidiyor, reject→resubmit **hiç denenmiyor**.

Oturumun ana teması, yedinci kez: mekanizma var, o yola giden test yok.

## Çözüm — tasarım §5.4 (bağlayıcı)
`docs/analysis/0008-on-off-invoice-envelope-design.md` §5.4:
- Gruplama anahtarı `envelopeId` → **`${envelopeId}|${spendType ?? 'UNTYPED'}`**; kova başına
  tek RELEASE, tutar = **net** (ham satır tipiyle değil — kural #4).
- RELEASE satırı ait olduğu kovanın `spendType`'ını **taşımalı** (UNTYPED kova için NULL kalır).
- **İki ayrı idempotency key uzayı (bağlayıcı):**
  ```
  UNTYPED : RELEASE|<SRC>|<sourceId>|<envelopeId>                  ← BUGÜNKÜ FORMAT, DEĞİŞMEZ
  tipli   : RELEASE|<SRC>|<sourceId>|<envelopeId>|<SPEND_TYPE>     ← YENİ
  ```
  Bugünkü format değişirse T-019 öncesi **zaten release edilmiş** kaynak ikinci kez release
  edilir (çift iade — [[T-029]] fix'inin düzelttiği hata). Risk R2.

## Sonuç — ölçülmüş kanıt

**Kırmızı ÖNCE üretildi** (teşhis körü körüne kabul edilmedi). `/submit-for-approval` ile
submit → reject → resubmit:

| Aşama | Fix ÖNCESİ (hata) | Fix SONRASI |
|---|---|---|
| submit | RESERVE ON=10000, OFF=4500 | aynı |
| reject | **1 tipsiz** RELEASE(14500, `spend_type=NULL`) | **2 tipli** RELEASE (ON=10000, OFF=4500) |
| resubmit | RESERVE **2'de kaldı** (beklenen 4), plan net katkısı **0** | 4 RESERVE (`\|GEN2` sonekli 2 yeni), net **14500** |

Fix sonrası gerçek key'ler (A17b): `RELEASE|PLAN|<planId>|<envId>|ON_INVOICE` ve `...|OFF_INVOICE`.
Resubmit key'leri (A17d): `RESERVE|...|ON_INVOICE|GEN2`, `RESERVE|...|OFF_INVOICE|GEN2`.

**COMMIT yolu denetlendi (varsayılmadı):** `commitReservedForPlan`/`commitAllReservedForPlan`
paylaşılan `releaseNetReservation` motorunu **kullanmıyor** (ayrı implementasyon) ve CONVERT-RELEASE
satırı zaten [[T-048]]'de `spendType` taşır hale gelmişti → bu kusur o yolda yok, değişiklik yapılmadı.

## Team Lead bağımsız doğrulama (2026-08-02)
- **UNTYPED key formatı birebir korunmuş** (R2/çift iade riski) — HEAD ile string karşılaştırması
  yapıldı, yalnız değişken adı `envelopeId` → `bucket.envelopeId`, üretilen string aynı
- **Mutasyon kanıtı (Team Lead kendi koştu):** kova anahtarı tipsizleştirildi
  (`${envelopeId}|UNTYPED` + `spendType: null`) → `tsc` **TEMİZ kaldı**, testler **KIRMIZI** ve
  çıktı tam eski hatanın imzası: tek `spendType: null` RELEASE(14500),
  key `RELEASE|PLAN|plan-001|env-001`. Geri alınca **22/22**
- `npx tsc --noEmit` temiz · unit **570/570**
- e2e **3 ardışık reset'siz koşum** (flag kapalı/açık/kapalı): her biri **211/211**,
  11/11 suite, [[T-047]] invaryantı üçünde de **PASS**, `ENV-2026-NKA-Q1 reserved=75.000` sabit
- **A16 tek başına yeşil** — tipsiz uzayda regresyon yok
- **Ledger korunumu:** her zarfta Σkova == `v_budget_summary.reserved_amount`, net >= 0
  (NKA-Q1 75000=75000, NKA-Q2 75000=75000, ECOM-Q1 0=0, TRAD-Q1 0=0)

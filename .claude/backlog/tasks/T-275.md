## Bulgu — `T-249`'un ERTELEDİĞİ iş, örtüsü kalktı

`T-249` şunu yazmıştı: *"`markAsRead(tenantId, id)` kullanıcıyı hiç almıyor — bir UUID
bilen herhangi biri…"* ve **bilinçli olarak ertelemişti**: *"`markAsRead`'in kullanıcı
almaması **ayrı** ele alınır."*

O gün geldi: `T-249`'un `GRANT`'i `500` örtüsünü kaldırdı, ve **içteki kusur artık
erişilebilir.**

### Kod — üç katmanda da yok

```
notification.controller.ts:93   markAsRead(@TenantId() tenantId, @Param('id') id)
                                ⛔ KULLANICI PARAMETRESİ HİÇ YOK
notification.service.ts:237     markAsRead(tenantId, notificationId)
notification.repository.ts:21   findById → where: { tenantId, id }
                                ⛔ recipientId sorulmuyor
```

### ⛔ POZİTİF KONTROL — mekanizma VAR, bu uç KULLANMIYOR

**Aynı repository dosyasında, aynı tablo:**

```
notification.repository.ts:33   find → where: { tenantId, recipientId }   ✅ kardeş
notification.repository.ts:21   findOne → where: { tenantId, id }         ⛔ bu uç
```

Yani eksik olan bir yetenek değil, **bir satır**.

### Davranışsal (architect, `SELF` turu, fixture kurulup silindi)

```
POZ.KONTROL  planner2 GET /notifications                      →  []      (okuma yüklemi ÇALIŞIYOR)
             planner2 POST /notifications/<ADMIN'in kaydı>/read  →  HTTP 200
DB           status PENDING → READ · read_at yazıldı          ⛔ ÇAPRAZ-KULLANICI YAZMA
YANIT        20 alan — recipientEmail · subject · body · metadata
                                                              ⛔ ÇAPRAZ-KULLANICI OKUMA
```

⚠️ **Yazma tarafı zaten kötü; okuma tarafı daha kötü** — yanıt gövdesi başka bir
kullanıcının bildirim **içeriğini** dönüyor.

## Sınıf

`CLAUDE.md`'nin *"bir kusur başka bir kusur tarafından örtülebilir"* maddesinin `#1`
vakasının **düzeltme sonrası hâli**: `T-249` bunu yazılı olarak öngördü, bugün ölçüldü,
ve **canlı**.

📌 Ve `SELF` taksonomisi açısından: bu uç **`SELF` değil, `SELF` OLMALIYDI.** İki kardeşi
(`GET /notifications`, `/unread`) yüklem taşıyor; bu üçüncüsü aynı ailede, aynı veri
sınıfında, **yüklemsiz**.

## ⛔ `SELF` KARARINI BEKLEMEZ

Bu bir taksonomi sorusu değil, **canlı bir açık**. Düzeltme `SELF` kovası açılmadan da
uygulanabilir ve uygulanmalıdır.

## 2026-08-23 — DÜZELTİLDİ

### `ŞART 1` — reprodüksiyon ÖNCE görüldü

```
fixture      ADMIN'e ait bildirim, subject "T-275 REPRO SECRET SUBJECT"
planner2 →   POST /notifications/<ADMIN'in id'si>/read
HTTP         200
DB           status PENDING → READ · read_at dolduruldu      ← ÇAPRAZ-KULLANICI YAZMA
YANIT        recipientEmail "admin@wella.com" · subject · body  ← ÇAPRAZ-KULLANICI OKUMA
```

**Kusur ve sızıntı doğrudan görüldü**, düzeltmeye ondan sonra geçildi.

### Düzeltme — üç katman

```
repository   findById(tenantId, id) → findById(tenantId, recipientId, id)
             where: { tenantId, recipientId, id }        ← kardeşleriyle AYNI şart
service      markAsRead(tenantId, recipientId, notificationId)
             bulunamama → NotFoundException (404), çıplak Error (→500) DEĞİL
controller   @CurrentUser('id') userId  alınıyor ve servise geçiyor
```

⚠️ `T-249`'un *"bilerek ertelendi"* yorumu da güncellendi — **yorum kirliliği kuralı**.

### Dört pin — davranışsal

| senaryo | ölçüldü |
|---|---|
| `PLANNER2` → `ADMIN`'in bildirimi | **`404`**, DB `PENDING` **kaldı** |
| `ADMIN` → kendi bildirimi (**poz.kontrol**) | `200`, DB `READ` |
| var olmayan id | `404`, **aynı şekil** — varlık sızmıyor |
| yanıt gövdesi | yalnız `{message, error, statusCode}` — `subject`/`body`/`email` **yok** |

📌 `404` seçimi bilinçli: `403` *"bu kayıt VAR ama senin değil"* der ve **varlığın
kendisini sızdırır**.

### Kardeş taraması (`§7.1`) — `notification.repository.ts`

| metot | `recipientId` WHERE'de | canlı çağıran |
|---|---|---|
| `findById` | ✅ **(bu turda düzeltildi)** | `markAsRead` |
| `findByRecipient` | ✅ zaten vardı | `GET /notifications` |
| `findUnreadByRecipient` | ✅ zaten vardı | `GET /notifications/unread` |
| `countUnread` | ✅ zaten vardı | ⚠️ **yok** — ölü kod |
| `create` | N/A (yazma) | ⚠️ **yok** — `createNotification`'ın üretim çağıranı yok |
| `update` | ✗ (primary-key `.save()`) | yalnız kapsamlı yollardan — **transitif güvenli** |

> **`findById` dışında sormayan-ve-canlı metot YOKTU.**

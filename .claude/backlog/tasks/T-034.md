## Açıklama
T-033 sırasında bulundu: `Plan` entity'sinde `@VersionColumn` **hiçbir mutasyon yolunda yok** —
`update`, `submit`, `approve`, `reject`, `returnToDraft`, FU/SKU düzenlemeleri dahil.
Agreement tarafı da kontrol edilmeli.

**BRD:** "Optimistic locking (eş zamanlı düzenleme)" — grid-heavy, çok kullanıcılı bir üründe
iki planner aynı planı aynı anda düzenlerse **son yazan kazanır**, diğerinin değişikliği sessizce kaybolur.
Settlement close'da `pessimistic_write` var (T-004), ama plan tarafı korumasız.

## Acceptance Criteria
- [ ] Mevcut durum taraması: hangi entity'lerde version kolonu var/yok (plan, plan_fu, plan_sku, agreement)
- [ ] Tasarım: optimistic locking nereye (entity `@VersionColumn` + servis katmanında çakışma → 409),
      grid'in sık güncellenen alt kayıtlarında (plan_sku volume) pratik mi
- [ ] Migration (version kolonları) + servis/DTO'ya version alanı
- [ ] Çakışmada anlamlı hata (409 + `code:'STALE_VERSION'`), frontend'in yeniden yükleyebilmesi
- [ ] Unit + e2e: eş zamanlı iki güncelleme → biri 409

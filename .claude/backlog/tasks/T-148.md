## Teşhis keskinleşti ([[T-143]] turu 12 / `docs/analysis/0030 §1`)

`Section_05 §5.1 Mode Coexistence (Critical Clarification)` — **dördüncü ve en tam ölçüm**:

> *"Planning-First and Actuals-First **can coexist within the same customer, channel, or
> portfolio** … This is **not a system-wide toggle**. A single user may create an
> Actuals-First agreement … **in the morning**, then work on a Planning-First JBP …
> **in the afternoon**."*

Dört faktör: tactic eligibility · **baseline availability (no baseline → Actuals-First)** ·
channel maturity · user role/permissions. **Glossary ile birebir aynı** — dört kaynak
uzlaştı.

> **Kod organizasyonu olarak `modes/` bölünmesi sorun DEĞİL.** Sorun, ayrımın **çalışma
> zamanında bağlamsal** olması gerekirken bugün **yapısal** olması: dört faktörden hiçbiri
> bir çözümleyiciye bağlı değil, çünkü `tactic_policies` tablosu yok.

⚠️ Ve *"no baseline → Actuals-First"* bu task'ı [[T-024]]'e bağlıyor: baseline kapsama
ölçümü yalnız veri kalitesi kapısı değil, **mod çözümünün girdisi**.

## 🔴 Mod çözümleyicisinin **kanonik tablosu** bulundu — ve o da yok ([[T-143]] turu 18)

Bu task `tactic_policies` üzerine açılmıştı. `Section_02 §2.6` **asıl çözümleyiciyi**
tanımlıyor:

```sql
scope_policies( channel, subchannel, cpl_id,
                execution_model,   -- ACTUALS_FIRST | PLANNING_FIRST | HYBRID
                default_workflow,  -- AGREEMENT | PLAN
                priority )         -- lower = higher priority
```

Örnek konfigürasyon (BRD'nin kendi tablosu):

| Channel | Execution Model | Default Workflow |
|---|---|---|
| Traditional | ACTUALS_FIRST | Agreement |
| **NKA** | **HYBRID** | Plan |
| Modern Trade | PLANNING_FIRST | Plan |
| Wholesale | ACTUALS_FIRST | Agreement |

Ve **CPL bazında override**: *"Carrefour → PLANNING_FIRST (even if channel is Traditional)"*.

> **İki tablo birlikte çalışıyor:** `scope_policies` **hangi modun** geçerli olduğunu,
> `tactic_policies` **hangi taktiğin o modda kullanılabileceğini** söylüyor.
> **İkisi de yok**, ve mod bugün bir **klasör**.

- [ ] Bu task'ın kapsamı `scope_policies`'i de içerecek şekilde genişletilsin
- [ ] ⏸️ `§2.6`'nın **Workflow Resolution Logic** bloğu (792–1026) okunmadan tasarım yapılmasın

## ✅ Algoritma bulundu — ve yığının **üç katmanı da** yok ([[T-143]] turu 19 / `0037`)

`§2.6 Workflow Resolution Logic`:

```typescript
const policy = getScopePolicy(tenantId, {channel, cplId});  // 1: bağlam
const perms  = getUserPermissions(userId);                  // 2: kullanıcı
// 3: kesişim →  ACTUALS_FIRST + 'agreements.create' → AGREEMENT
//               HYBRID + her ikisi → seçim modalı (default_workflow önerili)
return { workflows, autoSelect: workflows.length === 1 };
```

| # | katman | bizde |
|---|---|---|
| 1 | `scope_policies` (bağlam) | ❌ |
| 2 | yetenek izinleri (`agreements.create`) | ❌ rol enum'u ([[T-165]]) |
| 3 | `tenant_features.planning_mode_enabled` (faz) | ❌ |

### 📌 *"Kullanıcı seçmez"* ↔ HYBRID modalı çelişmiyor

**Mod** (`execution_model`) kullanıcı seçimi **değil** — bağlamdan gelir.
**Workflow**, HYBRID içinde kullanıcı seçimi — ama politikanın izin verdiği kümeden, ve
tek seçenek varsa `autoSelect` ile hiç sorulmadan.

> Soru altı turda kademe kademe cevaplandı. Sonuç: **ayrım gerekli, üç katmanı da
> yazılmamış.**

## Bulgu ([[T-143]] turu 3 / `docs/analysis/0021 §2`)

BRD `Section_04 §4.7` mekanizmayı **tam olarak** tanımlıyor ve `validateAgreement`'ın onu
yüklediğini yazıyor (`getTacticPolicy(tactic_id, 'ACTUALS')`):

```json
{ "tactic_id": "...", "mode": "ACTUALS",
  "allowed_mechanics": [...],
  "validation_rules": { "requires_fu": true, "requires_justification": true,
                        "max_duration_days": 30, "approval_threshold": 10000 },
  "budget_policy": { "requires_budget_check": true, "reserve_on_approval": true } }
```

**Ölçüm** (şema-nitelendirilmiş): `pg_tables WHERE schemaname='main' AND tablename LIKE
'%polic%'` → **BOŞ.**

## Neden P1

Bu tablo **dört ayrı şeyin** kanonik yeri:

| BRD'nin politikaya koyduğu | bugün nerede |
|---|---|
| `mode` (ACTUALS / PLANNING) | **modül dizininde** — `modes/actuals-first/`, `modes/planning-first/`; koda gömülü |
| `allowed_mechanics` | ölçülmedi |
| `max_duration_days` | `Section_04 §4.2` sabit 30 diyor; **§4.7 politika alanı olduğunu söylüyor** |
| `approval_threshold` | ölçülmedi (ADR 0002 ile ilişkili) |

⚠️ **Ve bu, mod ayrımının üç ölçümünü uzlaştırıyor.** Glossary ve §4.1 mod çözümü için iki
farklı faktör listesi veriyor; §4.7 **mekanizmayı** veriyor. Ortak öge *tactic eligibility*,
mekanizması bu tablo. (`0021 §2` — tur 2'nin "BRD-içi tutarsızlık" bulgusu geri çekildi.)

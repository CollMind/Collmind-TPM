## Bulgu (T-109 adım 2b sırasında ölçüldü)

`collmind.frontend/tsconfig.json:30` → `"include": ["src"]`.

```
npx tsc --noEmit --listFiles | grep -c "/tests/"     → 0
```

Ve kapının kör olduğu **kasten üretilen bir hatayla** doğrulandı:

```
tests/utils/numberUtils.test.ts sonuna:
  const DELIBERATE_TYPE_ERROR: number = "not a number";

npm run type-check → exit 0
```

Yani `npm run type-check` **hiçbir test dosyasını hiç denetlemedi.** Bu oturumda
onlarca kez "type-check exit 0" diye raporlanan kapı yalnız `src/`'yi kapsıyordu.

## Neden bu, aile üyesi

## Somut zarar — varsayımsal değil

T-109 2b'de `editingCell` ayrık birleşime çevrildi. Test fixture'ları **eski şekli**
kullanmaya devam etti ve `npm run type-check` **exit 0** verdi; uyuşmazlık ancak
`vitest` koşunca **8 kırmızı test** olarak göründü.

Daha kötüsü: fixture'lar üretimin **üretemeyeceği şekilleri** kurabiliyor ve tip sistemi
uyarmıyor. Bu turda tam olarak bu oldu — ikisi ölçülerek bulundu:

- `editingCell: { fuId, skuId, field }` (ikisi birden dolu) → **iki editör açılıyor**,
  ikincinin odağı birincisini blur edip **değişmemiş değerin gerçek PATCH'ini** gönderiyor
- SKU testi `editableAt: 'FU'` kolonuyla, yani üretimin hiç açamayacağı bir hücreyle koşuyordu

CLAUDE.md'nin "fixture ayırt ediciliği" kuralı bunu yakalamaya çalışıyor ama **insan
dikkatine** dayanıyor; tip sistemi bedava yapardı, ve kapsam dışı olduğu için yapmıyor.

## Sınıf: koruma eklendi, bir katman aşağıda yutuluyor

[[T-083a]]'daki yarım düzeltmenin akrabası, ama tersi yönde: orada mekanizma vardı, mesaj
eksikti; burada mekanizma **var ve çalışıyor**, sonucu bir `catch` siliyor.

## Bulgu

`dashboard.service.ts:126-131` (`code-reviewer`, T-097 review B3; Team Lead bağımsız doğruladı):

```ts
let budgetUtilization: DashboardSummaryResponseDto['budgetUtilization'] = null;
try {
  const raw = await this.financeReportingService.getBudgetUtilization(tenantId, budgetFilters);
  budgetUtilization = { ... };
} catch (err) {
  this.logger.warn('getBudgetUtilization failed — returning null', err);
}
```

**Ölçülen zincir:**

```
GET /dashboard/summary            (dashboard.controller.ts:42 — canlı rota)
  → DashboardService
  → FinanceReportingService.getBudgetUtilization
  → budgetAllocationRepository.find({...})     (finance-reporting.service.ts:129)
  → BudgetAllocation hidrasyonu
  → DecimalTransformer.from                    (9 transformer'lı kolon)
```

`from` artık ayrıştırılamayan bir değerde `InvalidDecimalError` fırlatıyor ([[T-097]]).
Bu rotada o hata **tam olarak `null`'a dönüşüyor** — T-097'nin ortadan kaldırmak için var
olduğu davranışa.

## İki ayrı kusur, ikisi de kapatılmalı

1. **Kapsam:** `catch (err)` her şeyi yakalıyor. Beklenen hata sınıfı ne? Yalnız o yakalanmalı.
2. **§2.5:** bir para KPI'ı için sessiz `null`. `budgetUtilization: null` gövdede "veri yok"
   demek — oysa gerçek "okunamadı". Frontend ikisini ayırt edemiyor.

⚠️ Bu bir T-097 regresyonu **değil** — catch önceden de oradaydı. Ama T-097 onu görünür
kılıyor: fırlatan bir koruma eklendi ve tek etkisi log satırı oldu.

## Karar gerekiyor (§2.4 — varsayma)

`getBudgetUtilization` başarısız olduğunda dashboard **ne yapmalı**? Üç seçenek ve hiçbiri
ajan varsayımıyla seçilemez:

- (a) Tüm `GET /summary` 500 dönsün — dashboard'un tamamı çöker, ama yanlış sayı gösterilmez
- (b) `budgetUtilization` alanı **hata durumunu taşısın** (`{ status: 'unavailable', reason }`)
      — DTO değişikliği, frontend işi
- (c) `null` kalsın ama **yalnız beklenen hata sınıfları** için, `InvalidDecimalError` yukarı
      geçsin

Ölçülmesi gereken: bu catch bugün **hangi** hataları gerçekten yutuyor (yani hangi gerçek
başarısızlık için yazılmış)? Git geçmişi ve çağrı yolu bunu söyleyebilir. Cevap yoksa **DUR.**

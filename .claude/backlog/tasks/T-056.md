## Adım 1 — DONE (2026-08-02): F1 net-tabanlı kova keşfi

**F1 (tasarım 0009):** `commitAllReservedForPlan` kova keşfi **ham RESERVE satırı varlığına**
bakıyordu, net'e değil. Reject append-only ledger'da RESERVE'ü değiştirmez, ayrı RELEASE yazar →
net'i sıfırlanmış TOTAL kovası yeniden keşfedilip **hayalet COMMIT** üretiyordu.

**Kırmızı önce üretildi** — çapraz yol (`/submit` → reject → return-to-draft →
`/submit-for-approval` → approve):
```
COMMIT ON_INVOICE        10000.00
COMMIT OFF_INVOICE        4500.00
COMMIT (spend_type=NULL) 14500.00   ← hayalet
```
Fix sonrası yalnız iki tipli COMMIT. [[T-033]] ve [[T-053]]'ün üçüncü kardeşi: *ham satır varlığı ≠ net*.

**Tek türetim noktası (Team Lead review'ünde geri gönderildi):** ilk teslimde `computeBucketNet`
eklenmiş ama `reserveForPlan` hâlâ kendi inline reduce'unu yapıyordu — aynı kuralın iki kopyası,
yani [[T-053]]'ü doğuran durumun ta kendisi. Ölçüm ikisinin **eşdeğer olmadığını** gösterdi
(`netOutstanding` ayrıca zarfa göre süzüyordu), bu yüzden körü körüne birleştirilmedi: kapsam
opsiyonel `envelopeId` parametresine dönüştürüldü ve inline reduce kaldırıldı.

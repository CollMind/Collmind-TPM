## Kök neden — üç satır

```ts
export const CurrentUser = createParamDecorator(
  (data: unknown, ctx: ExecutionContext) => {
    const request = ctx.switchToHttp().getRequest();
    return request.user;          // ← `data` HİÇ KULLANILMIYOR
  },
);
```

`@CurrentUser('id')` yazan her yer **tüm `request.user` OBJESİNİ** alıyor, string
`id`'yi değil.

## ⛔ En ağırı: `EA-001` self-approval koruması devre dışı

Kod kendi talebini onaylamayı **engellemek için yazılmış** ve karşılaştırma
**hiçbir zaman tutmuyor**. Yani koruma **var görünüyor ve hiç çalışmıyor**.

📌 `CLAUDE.md`: *"bir doğrulamanın çalıştığı sanılması, girdinin ona hiç ULAŞMAMASINDAN
gelebilir."* Burada girdi ulaşıyor ama **tipi yanlış**, ve karşılaştırma sessizce
`false` veriyor — `§2.5`'in tip tarafındaki hâli.

⚠️ **Ve `Z18`'in `READ_OWN` için verdiği "tam örnek" (`approvals/my-requests`) bugün
HİÇ ÇALIŞMIYOR.** Kod incelemesi *"yüklem var"* derdi ve **doğru** derdi — ama o
yüklem çalışan bir sorguya hiç varmıyor.

## ⚠️ DÜZELTME (2026-08-21, ölçümle) — `approve` FAIL-OPEN DEĞİLDİ

İlk yazımda *"kendi talebini onaylayabiliyorsun"* deniyordu. **Mutasyon koşumu
çürüttü:**

```
POST /approvals/:id/approve  →  500, DEĞİL 201
QueryFailedError: invalid input syntax for type uuid: "{"id":"…","sub":"…"}"
```

Yüklem gerçekten hiç `true` olmuyordu — ama istek korumayı geçtikten **SONRA** yazma
aşamasında patlıyordu (`updatedBy`/`approvedById` → obje → `uuid` reddediyor).

📌 **Yani self-approval bugün de mümkün DEĞİLDİ — ikinci bir kusur tarafından KAZARA
kapatılmıştı** (`INV-C-*`).

## Sonuç
Akış: architect (tasarım `docs/analysis/0003-...`) → backend (impl) → code-review → backend (fix).

- `budget-reservation.service.ts` (YENİ): net-tabanlı release motoru
  `net = Σ(RESERVE+COMMIT) − ΣRELEASE`, envelope bazında, `net>0` ise tek RELEASE.
  Idempotent (net-residual + unique index; 23505 → no-op, throw yok).
- `budget.repository.ts` transaction-aware (`manager?: EntityManager`) → RELEASE close'un
  queryRunner'ı **içinde** (rollback testiyle kanıtlı).
- `settlement-close` close'da release çağırıyor; `agreement.cancel()` yeni servise devredildi
  (cap-drift + tek-envelope kusurları kapandı); `reject()` defansif no-op.
- Backfill migration 1790: 17 CLOSED agreement × Σ 395.000 iade; tekrar çalıştırmada 0 satır.
- **Code-review 5. çift-sayım hatasını buldu** (T-029'un `releaseForPlan`'ı ham tip filtresiyle
  CONVERT'lenmiş RESERVE'i ikinci kez bırakıyordu → negatif rezerv/şişik available).
  Düzeltme: plan tarafı da aynı **ortak net motoruna** devredildi (`releaseNetReservation`)
  → altıncı tekrar yapısal olarak engellendi. Regresyon testi eklendi (hata test edilmediği için kaçmıştı).
- 418 unit + 121 e2e; DB invaryantları: negatif reserved 0, available>allocated 0,
  terminal-state asılı rezerv 0.

## Açıklama
T-027 doğrulaması sırasında DB kanıtıyla bulundu: agreement approve `RESERVE` budget
transaction üretiyor, ama **settlement close rezervi asla RELEASE etmiyor** → CLOSED
agreement'lar bütçeyi sonsuza dek tutuyor. Dev DB'de 22 CLOSED agreement × 20.000 =
440.000 RESERVE birikmişti; `ENV-2026-NKA-Q2` (600.000) fiilen tükenmişti
(available ≈ 10.000) → yeni onaylar "Insufficient budget" alıyordu.

T-004 kararı ("close budget'a YAZMAZ — çift-sayım") **consumed** için doğruydu;
ama **rezerv iadesi** ayrı bir konu: kapanan anlaşmanın kullanılmayan rezervi
serbest bırakılmalı. REJECTED/CANCELLED yolları da incelenmeli (aynı sızıntı olasılığı).

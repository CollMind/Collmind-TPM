## Kusur 1 — Escape kaydediyor

`PlanningGridEnhanced.tsx` FU editörü (`:1511` civarı) ve SKU editörü (`:1642` civarı):

```tsx
if (e.key === 'Escape') {
  onCellSave(planFu, undefined, col.code, currentValue);   // ← aynı değeri KAYDEDER
}
```

`handleCellSave` (`:1125`) bunu doğrudan mutasyona bağlıyor. Yani **iptal** eylemi:

- `PATCH` atıyor (`updateTacticMutation` / `updateVolumeMutation`)
- `version`'ı artırıyor → **başka bir kullanıcının açık düzenlemesi 409 alıyor**
- audit kaydı üretiyor (immutable, silinemez — §2.3)
- `fu-tactic-update` etiketli performans ölçümü başlatıyor
- ve iptalin kendisi `409 STALE_VERSION` ile **hata gösterebiliyor**

**İkinci madde en ağırı:** bir iptal, başkasının işini bozuyor. Optimistic locking'in tüm
anlamı **gerçek** bir değişikliğin çakışmayı yakalamasıdır; Escape sahte bir değişiklik
üretip o mekanizmayı yanlış tetikliyor.

Ve dördüncü madde ADR 0003'ü kirletiyor: `<500ms` telemetrisi iptal işlemlerini de sayıyor,
yani o ölçümlerin bir kısmı **hiç olmamış bir yazma**.

## Kusur 2 — geçersiz girdi hücreyi kilitliyor

Aynı editörlerde:

```tsx
onBlur={(e) => {
  const numValue = parseFloat(e.target.value);
  if (!isNaN(numValue)) { onCellSave(...); }   // ← else YOK
}}
```

Ve `setEditingCell(null)` **yalnız** `handleCellSave`'in içinde (`:1162`). Yani `abc` yazıp
blur edince: kaydedilmiyor, mesaj yok, **hücre düzenleme modunda kalıyor**.

**İkisi birlikte tam bir çıkmaz:** geçersiz değer girildi → blur kilitledi → Escape
yazmaya çalışıp başarısız oluyor. Kullanıcının çıkış yolu yok.

§2.5'in "`if` yazıp `else` bırakmamak" maddesi.

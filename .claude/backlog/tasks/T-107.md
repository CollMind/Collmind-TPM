```ts
const excelEpoch = new Date(1899, 11, 30);                    // YEREL gece yarısı
const jsDate = new Date(excelEpoch.getTime() + value * 86400000);
return jsDate.toISOString().split('T')[0];                    // UTC'ye göre biçim
```

**Ölçüldü (Team Lead, 2026-08-07):**

```
new Date(1899, 11, 30).toISOString()  →  1899-12-29T22:03:04.000Z
                                          ↑ Europe/Istanbul, o tarihte LMT +01:57
seri 46037 (hücrede 2026-01-15):
  mevcut yol  →  2026-01-14      ✗ bir gün geri
  Date.UTC    →  2026-01-15      ✓
```

`LMT +01:57` — standart saat dilimleri öncesi İstanbul yerel ortalama saati. Yerel gece
yarısı UTC'de bir önceki günün 22:03'ü; `toISOString()` UTC'ye göre biçimlendirince gün kayıyor.

**Bugün tetiklenmiyor** çünkü `raw: false` hiç sayı üretmiyor — dal ölü. Adım 2 onu uyandırır.

⚠️ Bu, `INV-N-003`'ün (fiscal period timezone bağımsız olmalı) somut bir örneği. Orada
`getFullYear()`/`getMonth()` için işaretlenmişti; **`Date` epoch kurulumu için değil.**
Invariant bu vakayı da kapsayacak şekilde güncellenmeli.

## Adım 2 — `raw: true`

Ürün sahibi kararı (2026-08-07): **(b) — sayıyı metne çevirme, kaynağında oku.**

> `raw: false` zaten sayıyı gereksiz yere metne çeviriyor. Excel hücresi `7250` **sayısını**
> tutuyor; biz onu `"7,250"` metnine çevirip sonra o metni sayıya geri ayrıştırmaya
> çalışıyoruz. Bilgi kaybının kaynağı dönüşümün kendisi — ve gramer, kaybolmuş bilgiyi geri
> getiremez.

**Ölçüldü — endişe edilen dönüşümler olmuyor:**

| kolon | `raw: false` | `raw: true` |
|---|---|---|
| quantity (`#,##0`) | `"7,250"` → **belirsiz, RED** | `7250` sayı ✓ |
| list_price | `"185.5"` | `185.5` sayı ✓ |
| customer_code | `"007"` | `"007"` ✓ **baştaki sıfır korunuyor** |
| sku_code | `"0012345678901"` | aynen ✓ |
| fiscal_period | `"2026-01"` | aynen ✓ |
| invoice_date | `"1/15/26"` (ABD biçimi, yerel ayara bağlı) | `46037` seri (belirsizlik yok) |

Metin hücreler `raw: true`'da **string kalıyor** — hücre tipi zaten metin olduğu için
`007 → 7` dönüşümü **olmuyor** (ölçüldü, varsayılmadı).

## Sınıf: **iki defter aynı kelime — AD-BORCU** · Öncelik: **P2** (ama `T-365`'i blokluyor)

`T-363` (danışman paketi Bölüm 1, halka 5 ölçümü) turunda hem koddan hem ekrandan bizzat ölçüldü.

## Ölçülmüş kusur

**Katman A — `budget_transactions.tx_type`:** enum'da `ALLOCATE · RESERVE · CONSUME · RELEASE` dört
değer var. Canlı DB: ALLOCATE 2 satır, RESERVE 4 satır, RELEASE (yalnız e2e'de), **CONSUME 0 satır** —
kod yorumu bunu itiraf ediyor: *"bu iki değer bugün hiçbir yazma yolunda kullanılmıyor"*
(`budget-transaction.entity.ts:9-12`).

**Katman B — `ledger_entries.entry_direction`:** `DEBIT`/`CREDIT` iki değerli, gerçek tüketim burada
yazılıyor (3 satır, `reversal.e2e-spec.ts:272` yön testiyle korunuyor).

**Frontend köprüsü — `BudgetLedgerPage.tsx:71-76`:**
```ts
const getTransactionType = (entry: LedgerEntry): TransactionType => {
  if (entry.entryDirection === 'DEBIT') return TransactionType.CONSUME;
  return TransactionType.RESERVE;
};
```
Ekranda ("Financial Ledger — Read Only") görünen "CONSUME" etiketi **Katman A'nın CONSUME'u değil**,
Katman B'nin DEBIT'inin bir çevirisi. Bu turda ekranda 3 "CONSUME" satırı görüldü — DB'de
`budget_transactions.tx_type='CONSUME'` **hâlâ sıfır**. İki cümle de doğru, ikisi de farklı katmandan
bahsediyor — ayrım hiçbir yerde yazılı değil.

## Seçenekler (ürün sahibi kararı — ajan seçmez, `CLAUDE.md §2.4`)

- **(a)** `budget_transactions.CONSUME/RELEASE`'i **öldür** — enum'dan çıkar, gerçek tüketim/serbest
  bırakma zaten `ledger_entries` + settlement akışında yaşıyor; `budget_transactions` yalnız
  ALLOCATE/RESERVE'i (rezervasyon defteri) tutsun.
- **(b)** `budget_transactions.CONSUME`'u **gerçekten yazan** bir yol ekle (settlement/RELEASE anında
  hem `ledger_entries` DEBIT hem `budget_transactions` CONSUME yazılsın) — iki defter senkron kalsın.
- **(c)** Frontend'deki "CONSUME" etiketini **yeniden adlandır** (`Tüketim (Defter)` gibi) ve UI'da iki
  farklı kaynağı ayıran bir ipucu/tooltip ekle — kod tarafına dokunma, yalnız isim netleşir.

Team Lead notu: `(a)` en az riskli görünüyor (`CLAUDE.md §7.1`: *"bir hatayı belgelemek onu koruma
altına alır"* — ölü enum'u canlı tutmanın maliyeti, onu kaldırmanın maliyetinden yüksek olabilir), ama
karar ürün sahibinindir.

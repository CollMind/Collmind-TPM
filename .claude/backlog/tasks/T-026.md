## Açıklama
Uçtan uca rol yolculuğu teşhisi (`test/role-journey.e2e-spec.ts`, 43 test) planning-first
akışının submit adımından itibaren kırık olduğunu kanıtladı. Üç kök neden:

1. **D-1 — submit-for-approval → 500:** `PlanApprovalHistory` entity `plan.module.ts`
   forFeature'da var ama `database.module.ts` merkezi DataSource `entities` listesinde YOK
   (`EntityMetadataNotFoundError`). Üstelik crash `updateStatus`'tan SONRA oluştuğu için
   plan DB'de `PENDING_APPROVAL`'a geçiyor → client 500 alırken state ilerliyor (limbo).
   [[T-021]]'de not edilen çifte entity kaydı tuzağının gerçek kurbanı.
2. **D-2 — approve → sahte "Insufficient budget" 400:** `budget.repository.ts
   checkBudgetAvailability` decimal kolonları transformer'sız string alıyor;
   `'500000.00' >= '8187.00'` LEXİCOGRAFİK false → geçerli onay reddediliyor.
3. **D-3 — finance-reporting/budget-utilization → 500 (her rol):**
   `BudgetAllocation.metadata` jsonb kolonu entity'de tanımlı, `main.budget_allocations`
   tablosunda YOK (migration eksik / şema kayması).

## Bulgu — `T-331` turunda çıktı, **ayrı sınıf**, düzeltilmedi

```ts
approval-workflow.service.spec.ts:1101-1102
  planRepo.findById.mockResolvedValue(approvedPlan);
  planRepo.findByIdForUpdate.mockResolvedValue(approvedPlan);   // ← AYNI nesne
```

İki metodun **tek ayrımı** şudur:
```
findById            relations: [... 'channel' ...]   ⇒ plan.channel DOLU
findByIdForUpdate   join'siz projeksiyon (KASITLI)   ⇒ plan.channel UNDEFINED
```
**Mock ikisini de aynı `relations`'lı nesneye bağlıyor ⇒ ayrım YOK EDİLMİŞ.**

## ⛔ ÖLÇÜLMÜŞ SONUÇ — kör, ve **İKİ YÖNDE BİRDEN**

```
kusur CANLIYKEN    1223 unit test YEŞİL · canlı uç KOŞULSUZ 400
kusur DÜZELİNCE    aynı test YİNE YEŞİL
⇒ test ne kusuru gördü, ne düzeltmeyi
```

`DISIPLIN`: *"fixture, ayırt etmek istediği iki tarafta **FARKLI DEĞER** taşımalı"*
(`§2.7 #4/#6`). Burada fixture **aynı değeri** taşıyor ve ayrım **mock'ta ölüyor**.

📌 Ve bu, `§2.7`'nin *"mock ile assertion aynı yanlışı paylaşabilir"* vakasının
(`T-116`) **kardeşi**: orada mock ile assertion **birbirine** uyuyordu ve ikisi
üretimden sapmıştı; burada mock **iki üretim metodunu birbirine eşitliyor**.

## İş
`findByIdForUpdate` mock'u **join'siz** bir nesne döndürmeli — yani gerçek metodun
sözleşmesini taklit etmeli:
```ts
const lockedPlan = { ...approvedPlan, channel: undefined };   // ya da omit
planRepo.findByIdForUpdate.mockResolvedValue(lockedPlan);
```

⛔ **REPRODÜKSİYON ZORUNLU, iki çıktı:**
```

2  düzeltme geri konur                                          → unit YEŞİL
```
Kırmızı **görülmeden** mock düzeltmesi kanıtlanmış olmaz.

## Açıklama

[[T-179]] **route kapılarını** düzeltti — doğru roller artık odaya girebiliyor. Ama
**sayfanın içindeki** rol kontrolleri ayrı bir kopya ve ikisi de bozuk, **zıt yönlerde**.

### 🔴 (a) Anlaşma onayı: **çok katı** — düğmeyi kimse göremiyor

```tsx
// AgreementApprovalsPage.tsx:475
{userRole === UserRole.MANAGER && ( ... Onayla / Reddet ... )}
```

`main.users`: **`MANAGER` = 0 kullanıcı** (2026-08-11 ölçümü). Ve bu **birebir eşitlik** —
`hasRole` çağrılmıyor, yani **`ADMIN` bypass'ı da yok**.

> **Backend'in gerçek onaycıları `CATEGORY_MANAGER` ve `FINANCE_MANAGER`**
> (`agreement.controller.ts:85-90`) ve **hiçbiri düğmeyi göremiyor.** `ADMIN` de göremiyor.
>
> T-179 onları odaya soktu; bu kusur düğmenin orada olmadığı anlamına geliyor.

### 🔴 (b) Plan onayı: **çok gevşek** — düğmede hiç kontrol yok

```
PlanApprovalsPage.tsx: userRole|hasRole|UserRole geçiş sayısı → 0
```

Onayla/Reddet düğmeleri **rol kontrolü olmadan** render ediliyor. `READONLY` görüyor,
tıklıyor, backend 403 veriyor.

### 📌 (c) `Sidebar.tsx` — **üçüncü** kopya

```tsx
:591  if (user?.role === 'CATEGORY_MANAGER') {
:594  if (user?.role === 'FINANCE_MANAGER' || user?.role === 'FINANCE') {
```

Ham string karşılaştırması, deprecated `'FINANCE'` dahil, ve route kapılarıyla senkron
olduğunun **garantisi yok**.

## ⛔ Asıl sorun tek tek düğmeler değil — **yetki dört yerde tanımlı**

```
backend @Roles  ·  routes/index.tsx requiredRole  ·  sayfa içi kontroller  ·  Sidebar
```

`CLAUDE.md §7`: aynı yetenek birden çok kez yazıldı — ve burada **dört kopya, üçü farklı
cevap veriyor**. [[T-179]] ikisini hizaladı; bu task kalan ikisini kapatır, ama kalıcı
çözüm **tek kaynak**tır.

## Yapılacak

1. **Doğruluk kaynağı backend** ([[T-179]]'un kuralı): her düğme için ilgili
   `@Roles(...)`'ı oku, `dosya:satır` ile yaz. Uydurma.
2. (a) ve (b)'yi düzelt — ve `hasRole` kullan (`ADMIN` bypass'ı ordan gelir), **birebir
   eşitlik yazma**.
3. `Sidebar`'ı route kapılarından türet ya da en azından deprecated string'lerden arındır.
4. **Say (`§7.1`):** sayfa içinde rol kontrolü yapan **başka** bileşen var mı? Cevap bir
   **komut çıktısı** olsun — `userRole ===` · `user?.role ===` · `UserRole.` desenlerini
   tüm `src/` üzerinde tara.

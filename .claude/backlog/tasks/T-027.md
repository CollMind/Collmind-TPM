## Açıklama
Rol yolculuğu teşhisi: seed'deki 166 SKU'nun HİÇBİRİNDE COGS yok; `plan.service.ts:627-628`
`Number(sku.cogs) || 0` fallback'i eksik COGS'u sessizce 0 kabul ediyor →
`planned_gp === planned_turnover`, `GP_ROI_PCT=%100`, RAG=GREEN. BRD kuralı: **eksik veri → null**.
Kullanıcı yanıltıcı "mükemmel" skor görüyor — T-008'de fallback'leri temizlemiştik ama
context kurulumundaki `|| 0` dönüşümleri kalmış.

## Acceptance Criteria
- [ ] Context kurulumunda `|| 0` fallback'leri kaldırıldı: COGS/unitPrice/BPTT eksikse

- [ ] RAG null KPI'da null/UNKNOWN (GREEN değil)
- [ ] Wella SKU seed'ine gerçekçi COGS eklendi VEYA (kaynak veride yoksa) COGS'suz SKU'larda
      null davranışı UI/rapora kadar taşınıyor — hangisi seçildiyse gerekçesiyle
- [ ] role-journey A5: ROI artık sahte %100 değil (COGS'lu SKU'da gerçek değer, COGS'suzda null)
- [ ] Set A sayısal paritesi (INCR_GP=695, ROI=%10.18) bozulmadı

## Sonuç
- `toNullableNumber()` helper: COGS/BPTT/BASE_VOL/PLAN_VOL eksikse context'e **null**
  (0 değil) → engine null-propagation → ROI/GP/RAG null (sahte %100/GREEN bitti).
  Meşru 0'lar korundu; aggregation `|| 0`'ları (ekran toplamı) bilinçli bırakıldı.
- Migration 1788: `plan_skus.planned_gp/planned_turnover` nullable; entity tipleri
  `number|null`; persist artık stale değer bırakmıyor (explicit null).
- Gerçek Wella SKU'larına uydurma COGS EKLENMEDİ (BRD varsayım yasağı);
  e2e fixture'ı `SKU-E2E-COGS-FIXTURE` (unitPrice=100, cogs=60) pozitif yolu kanıtlıyor.
- 395 unit + 112 e2e yeşil; Set A paritesi (INCR_GP=695, ROI=%10.18) korunmuş.

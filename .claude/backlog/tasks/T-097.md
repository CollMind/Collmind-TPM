## `docs/analysis/0014`'ün F1 fazı — tek yerinde düzeltilebilir kusur

```ts
from: (value?: string | null) => {
  if (value === null || value === undefined) return value;
  const num = Number(value);
  return Number.isNaN(num) ? null : num;   // ← iki kusur, tek satırda
}
```

**Kusur 1 — float dönüşümü.** ADR 0007 F1'de ölçülmüştü, T-090'da **yeniden doğrulandı**: tam
ondalık string IEEE-754'e giriyor. `INV-N-002` bunu yasaklıyor.

**Kusur 2 — sessiz null (YENİ).** Ayrıştırılamayan bir para değeri **"değer yok"a dönüşüyor**.
CLAUDE.md §2.5'in tam tanımı: *"finansal bir yolda çözülemeyen girdi → açık hata fırlat."*

## ⚠️ Spec kusurları KİLİTLİYOR

`decimal.transformer.spec.ts` yeşil (7 test, exit 0) ama `:13` float dönüşünü ve `:17` sessiz
null'ı **sözleşme yapıyor**. Bu oturumda üçüncü kez: test doğru davranışı değil **mevcut**
davranışı sabitliyor.

Düzeltme spec'i de değiştirmeli, ve **neden değiştiğini** yorumda söylemeli.

## ✅ Artık ratchet'e bağlı (F0, backend `ce63344`)

`src/database/` Alan A'ya alındı; bu dosyanın `Number(value)`'ı tabanın **168 bulgusundan
biri**. Yani kusur bir sayıya bağlı: düzeltilince taban düşer, düzeltilmedikçe görünür kalır.
`INV-N-002` için somut takip mekanizması.

## ⚠️ KAPSAM SINIRI — Kusur 2 bağımsız, Kusur 1 DEĞİL

**Kusur 2 tek başına düzeltilebilir:** NaN'da `throw`. Davranış değişikliği var ama dar —
bugün sessizce `null` dönen bir yol gürültülü hâle gelir, ve o yol bugün hiç tetiklenmiyor
olabilir (ölç).

**Kusur 1 tek başına düzeltilemez.** `docs/analysis/0014` ölçtü: `Number()`'ı kaldırmak
`MoneyMinor`'a geçmek demek, o da tanım gereği **her okuyucuyu** değiştirir — 5 entity'nin tüm
tüketicileri. Ve string'e dönmek T-026 regresyonudur (`'500000.00' >= '8187.00'` lexicografik).
`number` kalıp tam olmak imkânsız: 33 kolon `numeric(18,2)`, 2^53 üstü değerler temsil
edilemez.

Yani **"önce transformer'ı düzelt, sonra yay" diye iki aşamalı bir plan yok** — Kusur 1'in
düzeltmesi zaten yayılımın kendisi (F4), ve F4 `D-15`/`D-16`/`D-17` kararlarını bekliyor.

## ✅ KAPANDI — 2026-08-07, backend `e39feeb`

> ⚠️ İlk hâli (`bda6699`) review'da **yanlış bir ölçüm iddiası** taşıdığı için amend edildi.
> Aşağıdaki "REVIEW" bölümü ne değiştiğini anlatır.

### Ölçüm kusuru büyüttü: bir değil BEŞ yanlış davranış

```
""      → 0          ← SESSİZ SIFIR, task'ın tarif ettiğinden farklı ve daha kötü
"   "   → 0          ← aynı
"abc"   → null       ← bilinen (sessiz null)
"0x10"  → 16         ← onaltılık kabul ediliyor
"1e5"   → 100000     ← üstel kabul ediliyor
"Infinity" → Infinity ← Number.isNaN yakalamıyor, para değeri olarak SIZIYOR
```

Task *"sessiz null"* diyordu. Boş string `null` değil **`0`** üretiyor — yani §2.5'in doğrudan
yasakladığı sessiz sıfır, farklı bir dal.

### Kapsam: ikisi kapandı, dördü kapanamadı — ve bu kodda yazılı

`isFinite` **NaN ve Infinity**'yi kapattı. `""`/`"   "`/hex/üstel **`Number()`'ın kendi
davranışı** — kapatmak katı bir ayrıştırıcı gerektirir, o da `Number()`'ı kaldırmak, o da
`MoneyMinor` demek → **F4**, ve F4 `D-15`/`D-16`/`D-17`'yi bekliyor.

Spec'te **"STILL WRONG"** adlı iki test bu davranışı sabitliyor — boşluk sessizce görünmez
hâle gelmesin diye. Bir gün fırlamaya başlarlarsa bu **ilerlemedir** ve o blok taşınmalı,
sessizce silinmemeli.

⚠️ Kısmi koruma, tam koruma sanıldığında hiç korumadan tehlikelidir — bu oturumda **dördüncü**
örnek (kısmi transformer · dar guard · nullable kolonda UNIQUE · ve şimdi bu).

### "Ulaşılamaz" olmasına rağmen düzeltilmesinin gerekçesi

Ölçüm: NaN dalı bugün **ölü kod** — kolonlar `numeric`, Postgres kanonik metin döndürüyor.

Yine de düzeltildi, çünkü **transformer bir sözleşmedir ve sözleşmenin geçerliliği çağıranın
bugünkü şekline bağlı olamaz.** Bir DTO dönüşümü, bir import yolu, bir `getRawOne` hidrasyonu —
garanti o an zaten burada olmalı. F4'ü beklemek, üç açık ürün kararına bağlı bir faza bahis
oynamak olurdu.

### Eski spec kusuru kilitliyordu — üçüncü kez

`expect(from('not-a-number')).toBeNull()` — üstelik *"instead of NaN"* adıyla, yani sessiz
varsayılanı **dikkatli seçim** gibi gösteriyordu. Düzeltmeye kalkan biri kırmızı suite görüp
düzeltmenin yanlış olduğu sonucuna varırdı.

Eski assertion **silinmedi, spec'te alıntılandı**: mevcut davranışı kilitleyen bir testi
sonradan tanıyabilmek, onu temizce yok etmekten değerli.

## REVIEW — üç blocker, hepsi bağımsız doğrulandı

### B1 — "veritabanından ulaşılamaz" iddiası YANLIŞ (Team Lead hatası)

Koda şu yazılmıştı: *"every column carrying this transformer is `numeric`, and Postgres emits
canonical decimal text, so `from` sees valid input or `null`."*

Ölçüldü (PostgreSQL 16, şema `main`, port 5434):

```
insert into t (v numeric(15,2)) values ('NaN');   →  INSERT 0 1
select v::text                                     →  NaN
insert ... values ('Infinity');                    →  ERROR: numeric field overflow
```

**`numeric(15,2)` NaN'ı saklar ve `NaN` metni olarak döndürür.** Yalnız `Infinity` reddedilir,
o da scale kısıtı yüzünden. `pg` NaN'ı `String(value)` ile serileştiriyor, ve bu kolonlarda
CHECK constraint yok (ölçüldü: şema `main`'de `contype='c'` → ilgili kolonlarda yok).

**Hatanın biçimi en kötüsü:** normatif bir cümle olarak koda girdi. Bir sonraki mühendis
"gelemez" yazısını görüp yazma ucunu korumayı gereksiz sayardı. [[T-084]]'ün
*"must not be fixed to match"* vakasıyla aynı sınıf — **bir hatayı belgelemek onu koruma altına
alır**, ve yorum testten farklı olarak hiçbir zaman kırmızıya dönmez.

→ **Genel kural CLAUDE.md §2.7'ye eklendi:** "kod yorumunda 'ulaşılamaz' yazmadan önce ölç."

### Sıfırın ikinci açıklaması — §7.1 madde 4 işledi

89 numeric kolonun hepsi tarandı: **0 NaN satırı.** Ama "neden sıfır?" soruldu:

```
budget_allocations     0 satır   ← 9 transformer kolonunun hepsi burada
budget_envelopes       4
sales_actuals          3
sales_actual_batches   3
```

Sıfır, "yazma yolları temiz" demiyor — **taramanın kapsamı fiilen boş kümeydi.** Ve NaN bu kod
tabanında varsayımsal değil: `Number("010.00005.0000")` = NaN, yani [[T-089]]'un düzelttiği
string-aritmetiği kusurunun artığı. Kod NaN üretmişti, sadece diske yazacak kadar ilerlememişti.

### B2 — `to` koruması (bu commit'e alındı)

okunamaz** hâle gelirdi — onarım rotası dahil, çünkü o da repository kullanır. Öncesi: `null`
okunuyordu, yanlış ama **kurtarılabilir**. Sonrası: yalnız raw SQL.

guard her nullable para kolonunu yazılamaz yapardı. Daraltma, onu gerektiren string
vakasından **fazlasını** koruyor.
